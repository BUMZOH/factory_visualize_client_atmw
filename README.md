# Factory Production Dashboard

工場設備の稼働状況・生産実績・アラーム情報を、\
**日別・期間・詳細**の3つの視点から確認するためのTkinterダッシュボードです。

設備データはSQLiteデータベースから取得し、Matplotlibによるグラフや
Pillowによるタイムライン画像として表示します。

------------------------------------------------------------------------

## 1. アプリの構成

画面は左側のナビゲーションから切り替えます。

-   **日別**
    -   指定したエリアの複数設備を1日単位で比較
-   **期間**
    -   指定した1台の設備を期間単位で確認
-   **詳細**
    -   指定した1台・1日のタイムラインとアラーム履歴を確認

起動時は「日別」ページを表示します。

------------------------------------------------------------------------

## 2. 設計方針

このアプリでは、機能を小さな部品に分けて組み合わせる構成を採用しています。

``` text
Chart / Table
      ↓
     Tab
      ↓
    app.py
```

### Chart / Table

グラフやテーブルそのものを担当します。

-   DBから必要なデータを取得
-   データを表示用に加工
-   グラフやテーブルを更新

### Tab

1画面分のUIを担当します。

-   検索条件
-   キー操作
-   Chart / Tableの配置
-   検索実行
-   キャプチャ

### app.py

アプリ全体をまとめます。

-   メインウィンドウ
-   左サイドナビゲーション
-   ページ生成
-   ページ切り替え
-   アプリ終了処理

ファイル数を無理に減らすのではなく、\
**1ファイルの役割を分かりやすく保つこと**を優先しています。

## 4. 日別ページ

`tab_daily.py`

指定したエリア・対象日について、複数設備を比較します。

### 検索条件

-   対象エリア
-   対象日

対象エリアの設備番号・設備種類・使用DBは `factory_machine_layout.json`
から取得します。

### 表示グラフ

2×2で次の4グラフを表示します。

  位置   ファイル                         内容
  ------ -------------------------------- ------------------------------
  左上   `chart_regular_time_status.py`   定時内の機械稼働状況
  右上   `chart_operating_time.py`        定時内・定時外の機械稼働時間
  左下   `chart_production.py`            生産実績・目標
  右下   `chart_alarm_count.py`           アラーム発生数

### 日付操作

対象日のEntryでは次のキー操作ができます。

  操作         動作
  ------------ ------------
  `↑`          1日前
  `↓`          1日後
  `Ctrl + ↑`   前月へ移動
  `Ctrl + ↓`   翌月へ移動
  `Enter`      検索

------------------------------------------------------------------------

## 5. 期間ページ

`tab_period.py`

指定した1台の設備について、日ごとの変化を期間表示します。

### 検索条件

-   機械番号
-   開始期間
-   終了期間

初期値は次のとおりです。

-   機械番号：`1`
-   開始期間：今月の1日
-   終了期間：今月の月末

### 表示グラフ

2×2で次の4グラフを表示します。

  ----------------------------------------------------------------------------------------------
  位置                    ファイル                                内容
  ----------------------- --------------------------------------- ------------------------------
  左上                    `chart_regular_time_status_period.py`   定時内の機械稼働状況

  右上                    `chart_operating_time_period.py`        定時内・定時外の機械稼働時間

  左下                    `chart_production_period.py`            生産実績・目標

  右下                    `chart_alarm_count_period.py`           アラーム発生数
  ----------------------------------------------------------------------------------------------

期間グラフでは、指定した開始日から終了日までの日付を連続して生成します。
DBにレコードが存在しない日も横軸には残し、実際のゼロ値と
「データなし」を区別できるようにしています。

日付ラベルは `MM/DD` 形式で表示し、

-   土曜日：青
-   日曜日：赤

として休日を把握しやすくしています。

### 期間操作

開始期間・終了期間のEntryでは次のキー操作ができます。

  操作         動作
  ------------ ------------
  `↑`          1日前
  `↓`          1日後
  `Ctrl + ↑`   前月へ移動
  `Ctrl + ↓`   翌月へ移動
  `Enter`      検索

月単位で前後のデータを確認するときは、 `Ctrl + ↑ / ↓`
を使うことで日付の再入力を大幅に減らせます。

期間表示は任意の開始日・終了日に対応していますが、
通常の使用では**1か月程度**を想定しています。

------------------------------------------------------------------------

## 6. 詳細ページ

`tab_detail.py`

指定した1台・1日の詳細情報を表示します。

### 検索条件

-   対象機械
-   対象日

### タイムライン

`chart_status_timeline.py`

DBから1日分の設備ステータスを取得し、 `common_lib_mw.create_ope_graph`
を利用してタイムライン画像を生成します。

タイムラインは横スクロールに対応しています。

### アラーム履歴

`table_daily_alarm.py`

対象設備・対象日のアラーム履歴をTreeviewで表示します。

現在、アラーム履歴テーブルは `machine_operation.db` の `alarm_history`
テーブルを対象としています。

------------------------------------------------------------------------

## 7. グラフ内容

### 定時内の機械稼働状況

定時時間を基準として、設備状態を積み上げ表示します。

主な状態：

-   自動運転
-   材料切れ
-   段替え
-   刃具交換
-   アラーム
-   故障

定時は8:00～16:59の540分を基準としています。

### 定時内・定時外の機械稼働時間

自動運転時間を、

-   定時内
-   定時外

に分けて積み上げ表示します。

### 生産実績・目標

-   実績：棒グラフ
-   目標：折れ線

として表示します。

### アラーム発生数

設備ごと、または日ごとのアラーム発生数を棒グラフで表示します。

------------------------------------------------------------------------

## 8. 設備・DB設定

`factory_machine_layout.json`

設備の所属エリア、設備番号、設備種類、使用するDBを定義します。

概念的には次の構造です。

``` json
{
    "AreaName": {
        "db_file": "database.db",
        "machine_numbers": [1, 2, 3],
        "machine_types": ["TYPE1", "TYPE2", "TYPE3"]
    }
}
```

設備構成を変更するときは、できるだけPythonコードへ直接書かず、
このJSONを変更する方針です。

## 9. 使用データベース

現在、次のSQLiteデータベースに対応しています。

## 13. 開発時の基本ルール

新しい表示機能を追加するときは、基本的に次の順番で作ります。

1.  ChartまたはTableを単独で作る
2.  単独実行でDB取得・表示を確認する
3.  Tabへ組み込む
4.  必要なら `app.py` に新しいページを登録する

この順番にすることで、問題が起きたときに
**どの部品に原因があるかを切り分けやすくします。**

共通化は先に作り込みすぎず、重複が実際に問題になった時点で検討します。

## 15. 設計上の考え方

このプロジェクトでは、ファイル数の少なさよりも
**各ファイルの責任範囲が明確であること**を重視しています。

例えば期間表示を追加するときも、

``` text
期間用Chartを作る
        ↓
tab_period.pyで4つをまとめる
        ↓
app.pyへPeriodTabを登録する
```

という流れで追加できます。

既存の日別・詳細画面への影響を小さく保てるため、
機能が増えても修正箇所を判断しやすい構造になっています。

今後も、

**小さな部品を作る → Tabで1画面にする → app.pyで統合する**

という構成を、このダッシュボード開発の基本方針とします。
